# 0003 — Linux-first collection with a cross-platform seam

- **Date:** 2026-07-26
- **Status:** accepted
- **Decision:** The Node commits to **Linux-only in v1**, but the collection code is built behind trait + `#[cfg]` seams so Windows/macOS backends can be added later with no API change. Portable metrics (CPU%, mem, disk, net, processes) come from the cross-platform **`sysinfo`** crate; Linux-only richness (AMD GPU temps/power/clocks, per-core %, link carrier, precise sensors) is hand-rolled from `/sys`+`/proc` behind `#[cfg(linux)]`. Absent readings are `Option` (missing = `null`), so a device that can't report a metric simply reports less.
- **Why:** The fleet is heterogeneous and will grow beyond boxes the owner controls (friends' machines, future OSes). Committing to full cross-platform collection in v1 would triple the collection + packaging surface for reach nobody needs yet; localhost-first already implies Linux-first. `sysinfo` gives a portable floor for near-free, so the eventual Win/macOS backends are mostly a matter of enabling it, while the Linux-only detail that `sysinfo` can't provide stays isolated behind `cfg`. Graceful degradation + `missing = Option` (already decided) means "less info per device" is a normal state, not a special case — no per-device configuration required.
- **Consequences:** One extra dependency (`sysinfo`) carried on all platforms. Two collection paths on Linux (portable via `sysinfo`, enriched via sysfs/procfs) that must agree on the shared data model. Windows/macOS Nodes, non-NixOS Linux packaging, and any auth beyond localhost are explicitly deferred. The lib stays pure/sync (no `tokio`); the sampling loop lives in the Node binary, keeping the collection library generic and portable per this seam.
